# 通常の LLM に読書補助の中身（UI IR）まで生成させるか — 決定記録

- issue: #58
- 決定日: 2026-11-28
- 状態: **決定（案 A を継続。生成は下記の条件がそろうまで実装しない）**
- 関連: `AGENTS.md` §0.1（論点 E/F の 2026-11-27 追記）、§3.5、§8 / `docs/design/jev-adaptive-ui.md` / PR #57（選択の拡張、キャッシュ、中止・再開）/ コミット `a4ccfae`（旧生成経路の削除。プロンプトと検証の流れは `a4ccfae^` のツリーで参照できる）

## 1. 決定

**案 A（選択のみ）を継続する。** Decision Model（Jev など）も通常の LLM（Claude / GPT / GLM …）も、決定的に抽出した候補の中から **候補 id と数値（confidence / helps）だけ** を返す。モデルの出力が画面の中身になる経路は作らない。

将来、生成を入れるときは **案 C（種類を限定した生成）** の形に限る。案 B（あらゆる kind を生成し、照合で落とす）は採らない。案 C を実装する前に満たすべき規則を §3 に確定しておく。実装は別 issue で行い、そのときもこの文書の規則を変えずに使う。

## 2. 理由

| 観点 | 案 A（選択のみ） | 案 B（生成 + 厳格な検証） | 案 C（限定生成） |
|------|------------------|---------------------------|------------------|
| 捏造 | 構造的に起きない（中身は原文由来） | 数値・関係は照合できても、「その範囲が内容を裏付けるか」は機械的に判定できない | 数値を扱う kind を生成させないので、誤りは言い換えの範囲にとどまる |
| 出典 | 抽出時に `sourceRange` が確定 | 要素ごとに照合が必要。偽陽性・偽陰性が両方出る | 要約・論点には範囲照合だけを課し、表示で「生成・要確認」を明示 |
| 再現性 | 選択はキャッシュで安定 | 実行ごとに揺れる | 揺れるが、対象が文章だけなので影響が小さい |
| 送信範囲 | 見出し + 600 文字/節 | 本文の大半 | 対象節の本文（上限あり） |
| 価値 | 抽出できる範囲の補助だけ | 最大 | 散文の要約・論点という、抽出では作れない補助を足せる |

現状の補助（チャート、ノードグラフ、比較、チェックリスト、表、ディレクトリツリー、段階フロー）はすべて抽出で作れており、利用者からの要望（#61–#67）も抽出側の改善だった。生成で得られる追加価値は「散文の要約・論点」に集中している。一方で、チャートや比較カードは「事実の要約」に見えるため、そこに捏造が入ると本文より信用されてしまう。この非対称から、数値を扱う kind は今後も抽出だけにする（案 C の境界）。

## 3. 生成を入れるときの規則（案 C）

受け入れ条件の各項目に対する確定事項。

### 3.1 生成を許す kind と検証規則

| kind | 生成を許すか | 検証規則 | 上限 |
|------|--------------|----------|------|
| `SummaryCards` | 許す | 各カードに `sourceRange` 必須。範囲は対象節の中で、かつ実在する行。カード本文に含まれる数字（`\d`）と `` ` `` で囲まれた語は、すべてその範囲の原文に同じ文字列で現れること | カード 6 枚、各 200 文字 |
| `OpenQuestions` | 許す | 同上。問いの本文に原文にない固有名詞・数字を含めない | 10 件、各 160 文字 |
| `RiskPanel` | 許す（`Callout:risk` と同じ規則） | 同上 + `severity` は `info` / `warning` のみ（`error` は抽出だけ） | 8 件、各 200 文字 |
| `Chart` / `Comparison` / `DataTable` / `Timeline` / `NodeGraph` / `DirectoryTree` / `Checklist` / `StepNavigator` | **許さない**（抽出のみ） | — | — |
| その他の kind | 許さない | allowlist で reject | — |

- 出力は UI IR の JSON だけを受け付ける（`ir::validate_json`）。HTML / JS / Markdown を含む文字列はテキストノードとして描画し、`innerHTML` には渡さない（`AGENTS.md` §8）。
- 1 回の応答で返せるノードは節ごとに 1 つ。

### 3.2 検証で落ちた要素

- 落ちた要素は表示しない。ノードの全要素が落ちたらノードごと出さない。
- 理由はステータスに出す（`skipped` に `reason_code: "unverified"`、件数つき）。「なぜこの補助」ポップオーバーにも「生成した N 件のうち M 件を原文と照合できず除外」と出す。

### 3.3 表示上の区別

- 生成ノードは `origin = "llm"`。ヘッダに「生成・要確認」バッジを常に出し、低信頼（`confidence < 0.6`）なら既存の低信頼バッジも重ねる。
- 抽出ノードと同じ見た目の枠を使わない（左端に生成を示す帯を付ける）。

### 3.4 外部に送る本文の範囲と量

- 新しい設定 `[model] generate_chars`（既定 **2000 文字/節**、最大 8000）。選択用の `excerpt_chars`（既定 600）とは別にする。
- 送るのは対象節の本文だけ。前後の節、front matter、ファイルパスは送らない。
- 生成は既定で **オフ**（`[aids] generate = false`）。オンにしたときだけ、選択とは別のリクエストで送る。

### 3.5 キャッシュ

- キャッシュ鍵: 節の内容ハッシュ + モデル + プロンプト版 + `REGISTRY_VERSION`。
- ディスクには **生成テキストを書かない**（論点 E の 2026-11-27 追記と同じ方針。現在のディスクキャッシュは id と数値だけ）。生成物はプロセス内のメモリにだけ置き、再起動後は作り直す。
- これに伴うコスト（再起動ごとの再生成）は、既定オフと節単位の中止・再開（PR #57）で受け入れる。

## 4. この決定で変えないもの

- 選択（`select::*`）、キャッシュ（`select::cache`）、`[llm]`（Guided reading の解説文）の挙動。
- `AGENTS.md` §0.1 の論点 E/F の運用。生成を実装するときは、この文書の §3 を `AGENTS.md` に転記する。
